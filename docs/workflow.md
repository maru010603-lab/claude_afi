# 運用フロー

方針は [strategy.md](strategy.md)、プロンプトは [prompts.md](prompts.md)、公開条件は [compliance.md](compliance.md)。

## 1. 定期実行(クラウドルーティン「Claude Afi - Weekly Ops」)
平日(月〜金)日本時間6:53に1回起動し、**その日の曜日の作業だけ**を行う(土日は実行しない)。

| 曜日 | 作業 | 成果物 |
|---|---|---|
| 月 | KPI整理 | `reports/kpi.csv` の更新確認、未入力なら decisions.md に入力依頼(14日以内に依頼済みなら重複させない) |
| 火 | 体験談記事(プロンプト②) | `content/articles/YYYY-MM-DD_案件名.md`(実体験メモが無い部分は【実体験を記入】の空欄) |
| 水 | SNS告知投稿30本(X用15+Threads用15) | `content/sns/YYYY-MM-DD_week.md`(#PR付き、リンクは `{{ARTICLE_URL}}` のみ) |
| 木 | 案件リサーチ(プロンプト①、Web検索可) | `research/YYYY-MM-DD_cases.md`(根拠の無い数値は「要確認」) |
| 金 | 週次レポート | `reports/YYYY-MM-DD_weekly.md` |

- 保留カテゴリ(金融・保険・不動産)は、ゲートG5解禁まで記事化しない
- フェーズ2(Instagram)開始後は、水曜の作業にリール台本3本を追加
- 各実行の最後に decisions.md へ日付付きで1行報告し、git commit → push(pushは必須)

## 2. 人手が必要な工程(方針責任者)
1. ASP管理画面での案件確認(承認率・SNS掲載条件・否認条件・成果確定条件)
2. 実体験メモの提供(申込〜相談を実際に行った内容)
3. 記事の公開(note等。公開の最終操作は方針責任者)と、`{{ARTICLE_URL}}` / `{{AFF_LINK:案件名}}` の実リンクへの差替
4. KPI数値の入力(`reports/kpi.csv`)
5. アカウント作成・ASPメディア登録・各種認証

## 3. 投稿(Buffer無料プラン)
- 無料プランの制約: チャンネル3つ、1チャンネルあたりキュー10件まで、APIは個人APIキー方式(ベータ)
- フェーズ1はX・Threadsの2チャンネル、フェーズ2でInstagramを追加(計3チャンネル)。Instagramの予約投稿はビジネス/クリエイターアカウントが必要になる場合あり(要確認)
- 週30本は下書きとして保持し、キューの空き枠の範囲で順次補充する(API連携後は自動化)。上限を恒常的に超えるなら有料プランを相談する
- APIキーはルーティンの環境変数(`BUFFER_API_KEY`)としてclaude.aiの編集画面から方針責任者が直接設定する(値は統括に共有しない)
- API連携が済むまでは、下書きをBufferに方針責任者が貼り付ける

## 4. 動画(フェーズ2)
- Claudeはリール台本(テロップ案付き)まで担当。動画化は動画作成ツールで行う(ツール選定・費用は方針責任者と相談)
- 動画も断定表現・体験談の創作・効果表現の禁止ルールを適用(音声・テロップを含む)

## 5. トークン・実行量の管理
- 平日1回・1日1タスクに限定して消費を抑える(週5回)
- 実行ログは `RemoteTrigger list_runs` で確認。失敗が続く場合は原因を decisions.md に記載し、ルーティンを一時停止する
- 単純な量産(例: 投稿30本)はローカルセッションからCodex CLIへ委任してトークンを節約できる(クラウドルーティンからは不可)
