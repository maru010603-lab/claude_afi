# 運用フロー

方針は [strategy.md](strategy.md)、プロンプトは [prompts.md](prompts.md)、公開条件は [compliance.md](compliance.md)。

## 1. 定期実行(クラウドルーティン「Claude Afi - Weekly Ops」)
平日(月〜金)日本時間6:53に1回起動し、**その日の曜日の作業だけ**を行う(土日は実行しない=参考資料の週次リズム)。

| 曜日 | 作業 | 成果物 |
|---|---|---|
| 月 | KPI整理 | `reports/kpi.csv` の更新確認、未入力なら decisions.md に入力依頼 |
| 火 | 体験談記事(プロンプト②) | `content/articles/YYYY-MM-DD_案件名.md`(実体験メモが無い部分は空欄) |
| 水 | X告知投稿30本 | `content/x/YYYY-MM-DD_week.md`(30本、#PR付き、リンクは `{{LINE_URL}}` プレースホルダー) |
| 木 | 案件リサーチ(プロンプト①、Web検索可) | `research/YYYY-MM-DD_cases.md`(根拠の無い数値は「要確認」) |
| 金 | 週次レポート | `reports/YYYY-MM-DD_weekly.md` |

- 保留カテゴリ(保険・不動産)は公開ゲートG5解禁まで、リサーチ表には載せるが記事化・配信設計はしない
- LINE7通ステップ(プロンプト③)は、案件が確定しゲートG1を通過した案件について、該当日の作業の代わりに随時作成する
- 各実行の最後に decisions.md へ日付付きで1行報告し、git commit → push(pushは必須。GitHub側の書き込み権限が必要)

## 2. 人手が必要な工程(方針責任者)
1. ASP管理画面での案件確認(承認率・配信条件・広告主ガイドライン)
2. 実体験メモの提供(申込〜相談を実際に行った内容)
3. `{{LINE_URL}}` / `{{AFF_LINK:案件名}}` の実リンクへの差替
4. KPI数値の入力(`reports/kpi.csv`)
5. アカウント作成・ASPメディア登録・各種認証

## 3. 投稿(Buffer無料プラン)
- 無料プランの制約: チャンネル3つ、1チャンネルあたりキュー10件まで、APIは個人APIキー方式(ベータ)
- 参考資料は「週30本を予約」だが、無料プランのキュー上限は10件。30本は下書きとして保持し、Bufferへは空き枠の範囲で順次補充する(API連携後は補充を自動化)。上限を恒常的に超えるなら有料プランを相談する
- APIキーはルーティンの環境変数(`BUFFER_API_KEY`)としてclaude.aiの編集画面から方針責任者が直接設定する(キーの値は統括に共有しない)
- API連携が済むまでは、下書きをBufferの画面に方針責任者が貼り付ける

## 4. トークン・実行量の管理
- 平日1回・1日1タスクに限定して消費を抑える(週5回)
- 実行ログは claude.ai の Routines 画面と `RemoteTrigger list_runs` で確認。失敗が続く場合は原因を decisions.md に記載し、ルーティンを一時停止する
- 単純な量産(例: X30本)はローカルセッションからCodex CLIへ委任してトークンを節約できる(クラウドルーティンからは不可)
